Learning: one evidence project

This folder merges two earlier projects: the Kunskapsbank (a Swedish library of research sources on learning) and the Learning graph (a few claims about learning that are deliberately attacked). It was built on 2026-09-25. After everything was verified by checksum, the two old folders and their old site build folders were deleted the same day. This folder is now the only copy, kept as a local git repository (it contains source PDFs, so it is never pushed to a public remote).

The two guiding questions

Everything here has to serve one or both of these:

  1. Q1. What is optimal learning? (cognition, age and maturity, teaching, whatever the medium)
  2. Q2. How do we achieve it when AI and screens are everywhere? (Swedish school in practice)

What a claim is

A claim is one plain-language sentence about learning that could turn out to be wrong. Each claim file (claims/) says:

  • Claim: the sentence itself
  • Status: alive (not yet damaged), weakened (survived attacks but had to be narrowed) or killed (no longer tenable)
  • Bounds: where the claim applies and where it does not
  • What would kill this: the result that would make us drop it
  • Serves / Ages: which guiding question, and which age groups
  • Edges: how it relates to other claims (for example "C2 depends-on C1")

There are no numeric confidence scores anywhere in this project. Strength is shown only by status, bounds and the attack record.

How attacks work

Claims are kept under fire on purpose. An attack is one sentence that, if true, would change a claim's status. Each attack is logged in the claim's ledger (ledgers/) with a verdict:

  • survived: the attack did not change the claim
  • weakened (shown on the site as narrowed): the claim was rewritten narrower, or a bound was added
  • killed: the claim is dropped

The roles are described in method/ATTACKER.md (proposes attacks), method/CLERK.md (routes each attack: apply, hold or reject) and the writer, who updates the files. Only a human approves new claims.

Sources and links

sources/ holds one folder per research source. Original files (PDFs, abstracts, metadata) are copied byte-for-byte from the Kunskapsbank. Each folder also has:

  • NOTE.md: the Swedish summary written for the Kunskapsbank, kept verbatim (it used to be copied into several folders; now there is one copy)
  • LINKS.md: how the source bears on claims: supports, limits (agrees, but only under narrower conditions) or challenges (points against the claim; a queued attack, not a verdict)

All links are currently a first-pass draft, pending human review. They were generated from each note's "This claim dies if …" sentence and the ledgers, then reviewed once. links.tsv lists them all.

Candidates

candidates/ holds possible claims drawn from the Kunskapsbank. They are not approved. They have no ledger and are not in the brief. Only Jonatan can promote a candidate to a claim.

Inbox

inbox/ holds material that is not yet tied to any claim or candidate: sources without links, an uncatalogued source folder, and new sources waiting to be sorted. Being in the inbox says nothing about quality. It only means "not yet connected".

Other folders

  • brief.md: the current position, only living claims, in plain language
  • questions.md, edges.md, open-questions.md: the guiding questions, claim-to-claim edges, and at most 5 open questions
  • direction/: the Kunskapsbank's three practice and policy texts (Swedish, verbatim)
  • method/: inclusion rules (Swedish, verbatim) and the attack-lane role files
  • views/: explains the generated age and theme pages
  • reports/: attack campaign reports
  • archive/: old index files, theme READMEs and changelogs, the original C0/C1 claim files, the attack-lane role files as they were before the merge, old attack logs (archive/attack-logs/), and the full git history of the two old public sites as git bundles (archive/old-sites/, restore with git clone <file>.bundle)
  • sources.tsv: one row per source, with id, origin, ages and themes
  • CHECKSUMS-originals.sha256: checksums proving the original files are unchanged

The public site is built from this folder by a single build script and published with GitHub Pages.
